# Analysis: internationalisation of the web app

Backlog item 10. User request: make the application translatable and add
French first. Every user-facing string is written in English today,
directly in the Svelte templates and the TypeScript modules, and numbers,
durations and dates are formatted with a fixed `'en'` locale.

## Decisions (2026-11-03)

Taken with the user:

- **Library:** an in-house typed catalog (English source, French typed
  with the same shape, `Intl` for formatting), no dependency.
- **Scope:** the web app only, including biome names, generation stages,
  request errors and the built-in presets; generated files, the CLI and
  logs stay English.
- **Locale:** the browser's language on the first visit, overridden by an
  EN / FR selector that is remembered.

Formatting today:

- `lib/format.ts` builds `Intl.NumberFormat('en')` and
  `Intl.RelativeTimeFormat('en')`: French needs a decimal comma, a narrow
  no-break space before units and as thousands separator, and "il y a
  3 heures";
- `formatDuration` writes "3 min 05 s" by hand; units (km, km², °C, bar,
  g) are glued to numbers in templates;
- `index.html` declares `lang="en"`; the title is "Planets".

Outside the web app, text also lands in files: `legend.png` (drawn with
`font8x8`, ASCII only: no accents), `world.svg`, the biome names of
`world.json` and `raw_data`, the CLI help and its messages.

## Options

### Library

- **In-house typed catalog (chosen).** One module: an English
  catalog as the source (`messages/en.ts`, plain strings and functions for
  parameters and plurals), a French catalog typed with the same shape
  (`satisfies Messages`: a missing or extra key is a type error, caught
  by `svelte-check` in CI), a locale held in a Svelte 5 `$state`, and
  `Intl` for numbers, units, plurals (`Intl.PluralRules`), lists and
  relative times. About 100 lines, no dependency, no build step;
  parameters are typed (`t.jobs.eta({ seconds })`). Fits the app's size
  (two languages, ~350 messages) and the strong-typing preference.
- **Paraglide JS (inlang).** Compiles JSON message files into typed,
  tree-shaken functions through a Vite plugin; ICU-like plurals; tooling
  (extraction, editor extension, translation via the inlang ecosystem).
  Worth it with many languages or external translators; for two
  languages it adds a compile step, generated files and a project
  directory.
- **svelte-i18n.** Store-based, ICU message syntax at runtime
  (`intl-messageformat`, ~15 kB), keys are strings: no type checking of
  keys or parameters. Built around Svelte 4 stores.
- Not considered: typesafe-i18n (unmaintained since 2023).

### What gets translated

- **Web app: everything shown**, including biome names and generation
  stages, translated in the web from their stable keys, and the shortcut
  help. Shortcut keys stay the same in every language (`G`, `M`, `L`…):
  they are listed with translated labels, and the help stays the
  reference.
- **Server errors:** `RequestError` becomes a structured error,
  `{ error, code, params }` (`code` such as `out_of_range` with the field
  and its limits): the web translates known codes and falls back to
  `error`, which stays English for the CLI and `curl`. Other server
  errors (I/O, internal) keep their English text.
- **Presets:** built-in presets get their French name and description in
  their TOML, in an optional `[locales.fr]` table (`name`,
  `description`), passed through `PresetInfo.locales`; the web picks the
  active locale and falls back to English. Custom presets can do the
  same. The preset's `name` stays its identifier.
- **Not translated:** the files a generation writes (`legend.png`,
  `world.svg`, `world.json`, `raw_data`), the CLI, logs and the
  repository's documentation. They are data and tools shared across
  locales; `legend.png`'s font cannot draw accents anyway.

### Locale

- First visit: the first of `navigator.languages` whose language is
  supported (`fr-CA` → `fr`), else English.
- A language selector (`EN` / `FR`) in the header and in the shortcut
  help, remembered with the other settings (`lib/settings.ts`).
- `<html lang>` and the document title follow the locale; switching does
  not reload the page (the catalog is a `$state`).
- Deep links do not carry the locale: a link opens in the reader's
  language.

## Plan

| Step | Change                                                                                                                          | Seeds |

| 1    | i18n module (locale state, typed English catalog, `Intl` formatters), locale detection and selector, `lang` attribute           | Same  |

| 3    | Server: structured request errors (`code`, `params`), `[locales.*]` in presets and `PresetInfo.locales`; TS types               | Same  |
| 4    | French catalog, French names and descriptions of the built-in presets, glossary below; layout checked with longer strings       | Same  |
| 5    | Guard: a test that fails on literal text left in Svelte templates (allow-list for symbols and units), run in CI                 | Same  |

No step changes generated worlds. Steps 1 and 2 change nothing visible
(English only, with the selector hidden until step 4); step 4 turns
French on.

### Notes per step

- **Step 1:** `lib/i18n/` with `index.svelte.ts` (locale `$state`,
  `setLocale`, `t` getter), `en.ts`, `types.ts`, `format.ts` moved in
  (numbers, units with `Intl.NumberFormat` `unit` style where it exists:
  kilometre, celsius, percent; bar and g by hand). Unit tests: plural
  forms, French number and relative-time formatting, fallback for an
  unsupported locale.
- **Step 2:** mechanical but wide (every component): split by area into
  several commits so reviews stay readable; keys grouped by component
  (`t.viewer.layers.elevation`). Strings built by concatenation become
  messages with parameters, so word order can change in French.
- **Step 3:** `ApiError` gains optional `code` and `params`; the web's
  `ApiFailure` keeps them. Tests: each `RequestError` variant maps to a
  code; presets parse `[locales.fr]` and reject unknown fields.
- **Step 4:** French strings are about 20–30 % longer: check the display
  panel, the form's labels and the compare bar at phone width. Use
  typographic French (narrow no-break space before `:` `;` `?` `!`, `«
  »`), expressed with ` ` in the catalog.
- **Step 5:** the check scans `.svelte` templates for text nodes and
  `title`/`aria-label`/`placeholder`/`alt` attributes that are not
  expressions; a small allow-list covers symbols, units and proper names.

## Outcome

Done in one branch, a commit per area:

- **Catalogs:** `web/src/lib/i18n/en.ts` (about 330 messages, the
  source) and `fr.ts`, typed after it; `t` reads the active locale, a
  Svelte state, so the page switches language without a reload.
- **Formatting:** `lib/format.ts` formats numbers, units, durations and
  relative times in the active locale; French uses the decimal comma, a
  narrow no-break space before units, `:` and `%`, and a semicolon
  between latitude and longitude.
- **Server:** request errors carry `detail` (`ErrorDetail`, tagged by
  `code`) next to their English text; presets accept `[locales.<code>]`,
  served in `PresetInfo.locales` and not written to `world.json`, so
  worlds are unchanged.
- **Worker:** the decoding worker must not import the i18n state
  (`$state` is not compiled into worker bundles): the loading bar's text
  lives in `progressText.ts`, apart from `progress.ts`.
- **Layout:** the narrow header wraps instead of clipping; the selector
  shows the language codes.
- **Guard:** `templates.test.ts` fails on literal words in the markup;
  tests run in English whatever the machine's language.

## Open points

- Whether the CLI should ever follow the locale (`LANG`): not planned.
- A third language later only needs a catalog typed like the French one
  and the preset tables; a switch to Paraglide would only be worth it
  with external translators.
